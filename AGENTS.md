# Правила работы над Stash

Stash — простой self-hosted файловый сервис для 1–5 пользователей. Перед изменениями изучите текущую конфигурацию и не меняйте рабочее поведение без необходимости. Работайте небольшими этапами и проверяйте результат тестами.

## Структура

- `stash/auth/` — пароли, сессии, WebDAV-токены.
- `stash/database/` и `migrations/` — SQLite/SQLAlchemy и Alembic.
- `stash/files/storage.py` — файловая абстракция и безопасность путей.
- `stash/api/routes.py` — REST API.
- `stash/webdav/server.py` — WsgiDAV, авторизация и отображение пути пользователя.
- `stash/templates/` и `stash/static/` — HTML, CSS, vanilla JS.
- `stash/main.py` — ASGI-приложение, health check и жизненный цикл.
- `stash/__main__.py` — CLI и запуск сервера.
- `tests/` — интеграционные тесты.

## Архитектурные ограничения

Пользовательские файлы — обычные файлы с исходными именами в `data/users/{user_id}/files/`; SQLite содержит только служебные данные. Не переносите содержимое файлов в БД, не добавляйте UUID-имена или chunks. Все файловые операции должны использовать контекст `user_id` и не выходить за пределы его корня. Не разрешайте символические ссылки и traversal. Веб-интерфейс использует серверные сессии, WebDAV — только отдельные токены. Не добавляйте тяжёлые сервисы и frontend-фреймворки для функций MVP. Не логируйте пароли, cookie, токены или содержимое файлов.

## Проверка

```bash
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/python -m pytest -q
```

После изменения моделей добавляйте Alembic-миграцию. После изменения авторизации или путей добавляйте тест разделения пользователей и обхода каталога. Не меняйте этот файл без отдельного запроса владельца проекта.
